SANDBOX ONLINE · SB V1.3 OBSERVING

ONE FINDING, PLOTTED

Read one row at a time, nothing here is unusual.

Packages read files. Build tools run gzip. Installers write to temporary directories. What makes this a finding is the order the actions happened in, visible only while the code is running.

polymarket-stake-mathss@3.5.2 · 2 KB · ONE POSTINSTALL HOOK REVIEW
Nothing was taken. The container holds nothing real and is destroyed moments later, so what the package collected was a set of files that exist nowhere else.

Two kilobytes of readable JavaScript. No obfuscation, no packing, nothing a reviewer would catch by opening the tarball. The sequence is the signal.

INSTRUMENTATION

Two phases, traced apart, then merged

A payload that only fires on require() is invisible to anything that watches the install alone. So the run is split: the install is traced, then the package is loaded the way a consumer would load it and traced again, as a separate record.

PHASE 01 · INSTALL

Scripts enabled, on purpose

preinstall, install and postinstall all run, under full system call tracing, inside a container that starts from an identical pristine image every time.

Disabling lifecycle scripts is the safe way to install a package and the useless way to study one. The hook is where most of them put the payload.

Emits the install-phase record

PHASE 02 · IMPORT

Loaded, not just unpacked

The entry point is resolved and imported under the same tracing. Where a package declares no JavaScript entry, the run is marked no_js_entry rather than silently scored as quiet.

Import-phase findings are unioned with install-phase findings, not ranked below them. A credential file opened during install is no less interesting than one opened on import.

Emits the import-phase record

CORRELATED EVENT PAIRS · ONE RUN

Events are correlated as well as counted. A file made executable and then run, or a secret read and then compressed into an archive named after it, means something neither event means alone. Those joins are what a finding is made of.

ATTRIBUTION

An install is noisy. Only some of the noise is the package.

Every recorded action is tied back to the process that produced it. npm reads your .npmrc on every install; that is npm doing its job, not a finding.

DYNAMIC ENGINE · OUTPUT

Three groups of signal, every one attributed

The dynamic engine sets the verdict. What it emits per phase is a flat record under three headings. Empty is a result: a field with nothing in it is published as an empty list, not omitted, so absence of a signal is a fact you can query on.

the value is itself the concern context, kept for the baseline
network.package_connections

Every socket the package's own processes opened, as ip:port. Connections made by npm to the registry are attributed to npm and never appear here.

network.dns_lookups_non_npm

Resolutions to anything other than the registry. Held separately because exfiltration over DNS never opens a socket you would otherwise notice — the hostname is the payload.

network.exfil_services_contacted

A matched set of out-of-band callback and paste services. A hit here is close to conclusive on its own, which is why it is not folded into the general connection list.

canaries.canary_tokens_leaked

The container is seeded with fake credentials that exist nowhere else. If one leaves the sandbox, the package did not merely read a secret, it sent one. Nothing real is ever present to take.

canaries.accessed_by_package

Credential paths the package opened: SSH keys, cloud credentials, wallet files, CI tokens. Separated from ordinary reads because the target set is deliberate.

canaries.probed_but_absent

Paths it looked for and did not find. A package that stats a wallet directory it has no use for has told you its intent whether or not the file was there.

filesystem.dropped_and_executed

A path written or made executable during the run and then passed to execve. The single highest-value correlation the engine produces: neither half is remarkable alone.

filesystem.archives_written

Compressed output the package created. Named archives are recorded with the name intact, because attackers label their loot — ssh.gz, aws.gz, token.gz.

filesystem.recon_dirs_enumerated

Directory walks over home and root that no build step needs. Set alongside recon_dir_scan, which flags the pattern rather than the paths.

no_js_entry

True when there was no JavaScript entry point to import. Published explicitly so that "nothing ran" is never confused with "nothing happened".

STATIC ENGINE · OUTPUT

Reads the tarball, sets nothing

The published archive is examined without being run. Matches are split into two populations that are deliberately never mixed: threats, which carry a severity and a tactic, and capabilities, which carry neither because holding a capability is not an accusation. Almost every real package spawns a process or reads a file.

T

threat-*

Severity low / medium / high, plus MITRE tactics. Reported with the file, the line and the matched substring.

C

capability-*

What the code is able to do: outbound network, process spawn, filesystem write-executable, delete. Context only, never scored.

H

Per-file measures

SHA-256 for every file in the archive, and a normalised Shannon entropy score for every file under the size cap.

Rule names are hierarchical, and families collapse only when two or more rules share a stem. threat-runtime-obfuscation-{general,base64exec,steganography} gathers into one node; threat-runtime-environment-read, which shares its stem with nothing, stays at the top level rather than being dragged under a vaguer heading.

threat-process-download-exec high execution
Detects download-and-execute patterns: fetching a remote file then executing it
package/packages/cli/dist/index.cjs:43609
console.log( "\nFoundry (forge) was not found on your PATH.\nInstall it with:\n curl -L https://foundry.paradigm.xyz | bash && foundryup\n" );
match curl -L https://foundry.paradigm.xyz | bash

That one is a false positive, and it is shown here on purpose. The engine reports the match, the file, the line and the surrounding source, so you can dismiss it in two seconds instead of trusting a score you cannot inspect. A static rule that fires without showing its work is worth nothing.

Entropy

Shannon entropy over the 256 byte values, divided by eight, so the scale runs 0 to 1. Source and text sit around 0.52 to 0.65. Compressed, encrypted or packed data sits near 1. Anything at or above 0.94 is flagged — high-entropy content inside an otherwise readable package is the shape a bundled binary makes.

FILENORMALISED ENTROPY · 0 → 1
dist/internal/calc-mapping.bin 0.995
dist/index.mjs 0.642
types/index.d.ts 0.552
package.json 0.547
README.md 0.524
Files above the size cap are hashed but not measured. Those rows are published with entropy null and rendered as not measured, because a missing measurement and a low one are not the same claim.

The package above ships a 19 KB ELF binary at 0.995, loads it with fs.readFileSync, chmod 0755s it and spawns it — and the dynamic engine independently recorded that same path under dropped_and_executed. Two engines, one story. That agreement is what a REVIEW is built on.

READING THE FEED

Two verdicts, deliberately

A third tier invites arguments about which shade something is instead of whether to look at it. Where a run was cut short, the result is review, because no coverage is not the same as nothing found.

REVIEW

Behaviour a human should look at. A lead, not a conviction.

CLEAN

Nothing notable observed. Behaviour outside the observation window is out of scope.

Truncated runs

A run that times out or dies mid-trace resolves to review. The alternative is publishing a clean verdict backed by no observation, which is worse than publishing nothing.

Delisted packages

If the registry pulls a version while it is being analysed, it drops off the feed entirely rather than lingering as a record of something nobody can install.

Security placeholders

npm replaces a held version with a 0.0.1-security stub. There is nothing left to install and nothing to observe, so these stay, filed under review and marked as placeholders.

Clean is published too

Every analysed version carries a verdict, not only the bad ones. A feed of hits alone tells you nothing about the other 98 percent, and cannot be used as a baseline.
